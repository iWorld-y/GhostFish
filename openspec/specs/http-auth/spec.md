# http-auth Specification

## Purpose

让需要 HTTP Basic 认证的站点能正常打开：应用自己识别认证需求、取得并校验凭据、把凭据交给窗口发出请求。该能力只在服务器主动要求认证时介入，其余站点的行为不变。

## Requirements

### Requirement: 只在服务器要求 Basic 认证时介入

应用 SHALL 在后台探测启动参数或地址栏提交的网址是否需要 HTTP Basic 认证，不阻塞窗口启动。探测失败或重定向后，WebView 对当前主文档发出 Basic 质询时，应用 SHALL 继续处理该质询。网址里已带凭据时交给 WebView 处理。

#### Scenario: 站点要求 Basic 认证

- **WHEN** 启动时目标网址的首次请求返回 401，且质询方式为 Basic
- **THEN** 应用在后台进入取凭据流程，窗口无需等待探测和凭据输入

#### Scenario: 地址栏网址要求 Basic 认证

- **WHEN** 用户在空白标签页或已有标签页的地址栏提交网址，且目标网址首次请求返回 Basic 认证质询
- **THEN** 应用按现有顺序尝试获取凭据；没有可用凭据时，WebView 收到主文档质询后显示输入窗口

#### Scenario: 普通站点

- **WHEN** 目标网址返回 200，或返回 401 但质询方式不是 Basic
- **THEN** 应用不询问凭据，目标网页照常加载

#### Scenario: 网址里已经带了凭据

- **WHEN** 启动参数或地址栏提交的网址形如 `https://用户名:密码@主机/`
- **THEN** 应用不再探测、不再询问，交给对应标签页自己使用网址里的凭据

#### Scenario: 不提供启动网址

- **WHEN** 用户未提供启动网址，应用打开空白标签页
- **THEN** 应用不为该空白页发起 HTTP 认证探测或询问凭据

#### Scenario: 多个主机的认证质询

- **WHEN** 不同标签页分别打开要求 Basic 认证的不同主机
- **THEN** 应用只将为目标主机准备的凭据交给该主机的 Basic 质询，并分别限制被拒凭据的重试次数

#### Scenario: 探测失败后的主文档质询

- **WHEN** 预先探测失败，但 WebView 对当前主文档收到 Basic 质询
- **THEN** 应用允许用户在认证窗口输入凭据，不依赖探测结果弹窗

#### Scenario: 跨来源重定向

- **WHEN** 主文档重定向到不同来源并收到 Basic 质询
- **THEN** 应用要求用户输入，不自动将原来源的凭据发送给新来源

#### Scenario: 取消或切换页面

- **WHEN** 用户取消认证、关闭标签页或窗口，或导航到其他地址
- **THEN** 应用取消待处理认证并丢弃过期结果，不用旧凭据加载其他页面

#### Scenario: 切换标签页

- **WHEN** 用户在认证窗口输入期间切换到其他标签页
- **THEN** 原标签页的认证窗口隐藏并保留输入；切回后窗口恢复，后台标签页的认证窗口不会抢占当前页面

#### Scenario: 无关质询

- **WHEN** 代理、其他主机或非 Basic 认证发出质询
- **THEN** 应用不提供当前主文档的凭据

WebView 接口不提供质询的资源地址。主文档切换期间，应用无法可靠区分同主机同端口的子资源质询。

### Requirement: 凭据按固定顺序获取

应用 SHALL 依次尝试环境变量 `GHOSTFISH_AUTH`（格式为用户名冒号密码）、系统钥匙串、终端输入，并使用第一个可用的来源。钥匙串凭据按协议、主机、端口和 realm 组成的保护空间分别保存和读取。没有可用终端和凭据时，应用 SHALL 提供用户名和密码输入窗口。

#### Scenario: 环境变量优先

- **WHEN** 环境变量存在且形如 `用户名:密码`
- **THEN** 应用直接使用它，不读钥匙串也不提示输入

#### Scenario: 使用已保存的凭据

- **WHEN** 环境变量不存在，钥匙串里存有当前保护空间的凭据
- **THEN** 应用直接使用它，不提示输入

#### Scenario: 不同保护空间

- **WHEN** 钥匙串中只有其他协议、主机、端口或 realm 的凭据
- **THEN** 应用不读取或发送该凭据

#### Scenario: 旧的仅主机条目

- **WHEN** 钥匙串中只有旧版本按主机保存的凭据
- **THEN** 应用保留该条目，但不自动读取或迁移，用户可以重新输入凭据

#### Scenario: 需要用户输入

- **WHEN** 前两个来源都没有，且终端可用
- **THEN** 应用在终端询问用户名和密码，密码输入时不回显

#### Scenario: 拿不到凭据

- **WHEN** 三个来源都不可用，例如没有终端
- **THEN** 应用不阻断启动，并在主文档收到 Basic 质询时显示输入窗口；密码输入时遮挡

### Requirement: 凭据校验后记住

应用 SHALL 用取得的凭据请求目标网址进行校验；校验成功且 WebView 实际使用该凭据后，应用 SHALL 尝试将其存入系统钥匙串。

#### Scenario: 校验通过

- **WHEN** 用凭据请求目标网址返回 2xx 或 3xx，且 WebView 实际使用该凭据
- **THEN** 应用尝试将凭据写入系统钥匙串，并使用它完成本次页面加载

#### Scenario: 校验未通过

- **WHEN** 用户输入的凭据校验返回 401
- **THEN** 应用不写入钥匙串，仍可由 WebView 尝试；服务器再次拒绝时显示错误并允许用户修改重试

#### Scenario: 校验请求无法判断

- **WHEN** 校验请求失败或返回无法确认凭据有效性的状态
- **THEN** WebView 可以尝试该凭据，但应用不将其写入钥匙串

#### Scenario: 钥匙串不可用

- **WHEN** 写入系统钥匙串失败，例如用户拒绝授权
- **THEN** 应用照常继续，只在终端说明本次没能记住凭据

### Requirement: 凭据被拒时停止重试

应用 SHALL 限制同一份凭据交给窗口的次数；服务器反复拒绝同一份凭据时，应用 SHALL 停止提供并给出可读提示，不得让窗口持续重发请求。

#### Scenario: 密码错误

- **WHEN** 窗口带着应用给的凭据请求后仍被要求认证
- **THEN** 应用停止自动提供同一份凭据，并显示错误提示，允许用户主动修改后重试

#### Scenario: 重试不再发生

- **WHEN** 应用已停止提供凭据
- **THEN** 该页面的请求以失败或 401 结束，不再出现每分钟成百上千次的重试

### Requirement: 凭据不落明文文件

应用 SHALL NOT 把密码写进配置或状态文件；需要跨重启保留时只用系统凭据存储。

#### Scenario: 检查磁盘

- **WHEN** 用户认证成功后查看应用数据目录
- **THEN** 目录里只有窗口位置、不透明度和穿透状态，没有密码
