# Spec Delta

## Purpose

让需要 HTTP Basic 认证的站点能正常打开：应用自己识别认证需求、取得并校验凭据、把凭据交给窗口发出请求。该能力只在服务器主动要求认证时介入，其余站点的行为不变。

## ADDED Requirements

### Requirement: 只在服务器要求 Basic 认证时介入

应用 SHALL 在打开窗口之前用一次请求判断目标站点是否需要 HTTP Basic 认证；不需要认证、探测失败或网址里已带凭据时，SHALL 按原样加载，不产生任何提示。

#### Scenario: 站点要求 Basic 认证

- **WHEN** 目标网址首次请求返回 401，且质询方式为 Basic
- **THEN** 应用进入取凭据流程，并在窗口出现前把凭据准备好

#### Scenario: 普通站点

- **WHEN** 目标网址返回 200，或返回 401 但质询方式不是 Basic
- **THEN** 应用不询问凭据，窗口照常打开

#### Scenario: 网址里已经带了凭据

- **WHEN** 启动参数形如 `https://用户名:密码@主机/`
- **THEN** 应用不再探测、不再询问，交给窗口自己使用网址里的凭据

### Requirement: 凭据按固定顺序获取

应用 SHALL 依次尝试环境变量 `GHOSTFISH_AUTH`（格式为用户号码冒号密码）、系统钥匙串、终端输入，并使用第一个可用的来源。

#### Scenario: 环境变量优先

- **WHEN** 环境变量存在且形如 `用户名:密码`
- **THEN** 应用直接使用它，不读钥匙串也不提示输入

#### Scenario: 使用已保存的凭据

- **WHEN** 环境变量不存在，钥匙串里存有该主机的凭据
- **THEN** 应用直接使用它，不提示输入

#### Scenario: 需要用户输入

- **WHEN** 前两个来源都没有，且终端可用
- **THEN** 应用在终端询问用户名和密码，密码输入时不回显

#### Scenario: 拿不到凭据

- **WHEN** 三个来源都不可用，例如没有终端
- **THEN** 应用不阻断启动，窗口照常打开，并在终端说明没有拿到凭据

### Requirement: 凭据校验后记住

应用 SHALL 用取得的凭据真实请求一次目标网址来校验；校验通过时 SHALL 把凭据存入系统钥匙串，同一主机此后不再询问。

#### Scenario: 校验通过

- **WHEN** 用凭据请求目标网址没有返回 401
- **THEN** 凭据被写入系统钥匙串，并用于本次页面加载

#### Scenario: 校验未通过

- **WHEN** 校验请求返回 401 或请求失败
- **THEN** 应用在终端说明服务器返回的状态码，仍然把凭据交给窗口尝试，且不写入钥匙串

#### Scenario: 钥匙串不可用

- **WHEN** 写入系统钥匙串失败，例如用户拒绝授权
- **THEN** 应用照常继续，只在终端说明本次没能记住凭据

### Requirement: 凭据被拒时停止重试

应用 SHALL 限制同一份凭据交给窗口的次数；服务器反复拒绝同一份凭据时，应用 SHALL 停止提供并给出可读提示，不得让窗口持续重发请求。

#### Scenario: 密码错误

- **WHEN** 窗口带着应用给的凭据请求后仍被要求认证
- **THEN** 应用最多再给一次，随后停止提供凭据，并在终端提示用户名或密码大概率不对

#### Scenario: 重试不再发生

- **WHEN** 应用已停止提供凭据
- **THEN** 该页面的请求以失败或 401 结束，不再出现每分钟成百上千次的重试

### Requirement: 凭据不落明文文件

应用 SHALL NOT 把密码写进配置或状态文件；需要跨重启保留时只用系统凭据存储。

#### Scenario: 检查磁盘

- **WHEN** 用户认证成功后查看应用数据目录
- **THEN** 目录里只有窗口位置、不透明度和穿透状态，没有密码
