# Design

## Context

GhostFish 使用 MyGo 的原生界面承载标签栏和独立的系统 WebView。当前仅标签栏空白区域调用 `DragWindow()`，窗口创建于 `main.go`，位置由窗口的 `StateKey` 记录。设置只在 macOS 提供，四组全局快捷键使用带主键的 `shortcutBinding`；点击穿透通过窗口忽略鼠标事件实现。

行为范围见 `proposal.md` 和两个规格。MyGo 0.8.3 提供 `Window.NativeHandle()`，macOS 上返回 `NSWindow`。应用已有通过 `purego` 调用系统框架的方式，可以沿用无 cgo 的构建约束。

## Goals / Non-Goals

**Goals:**

- 在网页和应用控件接收鼠标之前判断拖动组合，并优先把移动交给 macOS 窗口系统。
- 将拖动组合与现有全局快捷键分开保存，沿用设置草稿、校验和保存失败回滚规则。
- 保持旧状态文件、点击穿透以及 Windows 和 Linux 的现有行为。

**Non-Goals:**

- 不增加系统范围的窗口管理功能，不修改其他应用或第三方网页。
- 不支持普通主键、Fn/Globe，也不新增跨平台设置界面。

## Decisions

### 在应用窗口的原生事件层判断拖动

优先评估 AppKit 的本地事件监听器：仅处理发送到 GhostFish 目标窗口内容区域的左键按下事件，比较事件中的 Command、Control、Option 和 Shift 状态与生效组合。未匹配时原样交还事件；匹配时使用原始按下事件调用目标 `NSWindow` 的 `performWindowDragWithEvent:`，并阻止该次按下继续传给网页或控件。这样不需要为各标签页注入脚本，也不依赖 WebView 内部元素是否处理鼠标。

调用发生在主线程；窗口关闭时移除监听器，避免失效句柄和回调泄漏。原生接口启动后可能不向应用发送鼠标松开事件，因此不能仅靠应用收到 `mouseUp` 来结束或重置拖动状态。启动后由窗口系统处理拖动，下一次按下应能独立判断。

候选方案必须先通过真实窗口验证，尤其是前台和后台窗口、WebView、应用控件及多显示器。AppKit 本地监听器不接收某些嵌套事件跟踪循环中的事件；若目标区域的事件无法到达，先评估合适的应用内原生接入点，不得把只覆盖标签栏的实现当作满足规格。若系统移动在实际环境中无法可靠启动，可评估最小坐标回退；回退必须保持鼠标相对位置、松开左键结束及既有窗口状态保存，并先验证多显示器行为。

备选方式是在网页注入脚本或在整个界面上覆盖拖动层。前者改变第三方页面的事件环境，后者可能阻断普通点击、文本选择和网页拖拽，因此不作为首选。

### 单独表示拖动修饰键组合

在 macOS 设置中单独保存一个非空修饰键集合，允许选择 Command、Control、Option、Shift 的任意组合。界面可使用四个选择控件，避免把只有修饰键的组合塞入现有要求主键的快捷键录入器。匹配时只比较这四个键的状态，组合必须完全一致；其他状态键不参与比较。

拖动组合不是新的全局快捷键注册项。原有四组快捷键的注册、录入、恢复与失败处理保持原有职责，按键本身不因拖动设置被全局占用。新值进入设置草稿，经校验和持久保存成功后生效；取消或保存失败时保留原来的生效值。

### 独立处理旧配置和损坏字段

缺少拖动设置的旧文件使用仅 Command 的默认组合。拖动字段无效时只回退该字段，并保留可独立解析的不透明度范围、已有四组快捷键、透明度和穿透状态。保存成功后重启应恢复所选组合；移动后的窗口位置继续由现有窗口状态机制记录。

相比扩展现有四项快捷键数组，独立字段不改变旧数组的长度、主键校验和全局注册语义，也更容易分别回退损坏的字段。

## Risks / Trade-offs

- [原生事件接入不覆盖所有内容区域或后台窗口] → 使用真实窗口逐项验证；若事件未送达，调整接入点后重新验证，不以单元测试代替系统事件验证。
- [匹配组合的单击可能被拦截] → 按已确认的行为处理，并在设置或使用说明中说明；Control 组合可能影响 Control 加单击的上下文菜单。
- [原生拖动后没有应用级鼠标松开事件] → 不以该事件作为唯一的状态清理依据，验证连续拖动以及先松修饰键、后松鼠标的行为。
- [旧设置读取或写入失败导致其他设置丢失] → 独立解析新字段，覆盖缺失、损坏、保存失败和取消修改的测试。
- [系统移动或回退在多屏幕、不同缩放比例下偏移] → 验证光标与窗口的相对位置、跨屏拖动和位置重启恢复；未能验证的环境明确记录。

## Migration Plan

1. 新版本读取旧状态时为缺失或无效的拖动字段使用 Command；只在正常保存设置时写入新字段。
2. 更新 macOS 的设置说明及拖动操作说明，保留现有四组快捷键的含义。
3. 回退到旧版本时，旧版本忽略新增的状态字段并继续读取已知设置；验证该兼容行为，不修改旧字段格式。
