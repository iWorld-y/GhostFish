# Design

## Context

当前窗口由 MyGo 原生界面承载标签栏、地址栏和各标签的独立 WebView；窗口控制由四组全局快捷键完成。`state.json` 保存当前不透明度和穿透状态，窗口位置与尺寸由框架保存。快捷键在启动时逐项注册，macOS 的长按连发只识别现有两组固定的不透明度快捷键。

设计稿的 HTML 仅模拟设置，不访问网页、不注册系统快捷键，也不持久保存设置。变更以规格中的应用行为为准，不将原型辅助控制区或终端模拟搬入应用。

## Goals / Non-Goals

**Goals:**

- 使设置界面、保存的配置、已注册的快捷键和实际窗口状态保持一致，并在失败时说明实际结果。
- 在 macOS 根据可观察到的注册结果保护穿透及隐藏状态，并兼容旧版状态文件；Windows 和 Linux 保持原有行为。
- 将配置校验和快捷键管理与界面绘制分离，便于测试失败与回滚路径。

**Non-Goals:**

- 不改变网页内容、认证或标签页会话，也不增加托盘、菜单栏图标和置顶开关。Windows 和 Linux 的设置界面及自定义快捷键留待后续变更。
- 不承诺系统允许注册任意键位；可录入的组合以当前平台能识别和注册的组合为限。

## Decisions

### 1. 使用独立的设置草稿和原生界面

macOS 标签栏按最新设计使用铺满栏高的直角当前标签，以左右分隔线区分；指针悬停时整块标签显示反馈。新建按钮与标签栏等高，加号在按钮内水平和垂直居中。标签栏右侧在平台窗口按钮预留区域内放置设置入口。打开时复制生效配置作为草稿，编辑、录入及校验只修改草稿；取消或关闭丢弃草稿，保存成功后才更新生效配置和关闭界面。录入状态下 Escape 只取消录入，界面保持打开。

使用 MyGo 原生界面实现设置面板，并保留标签栏、WebView 与拖动区域。macOS 最小验证确认原生弹窗可以覆盖 WebView，释放全局注册后输入控件可以接收组合键；实现时还需验证窗口按钮和窄窗口布局。不向第三方页面注入设置控件，也不以原型 HTML 代替应用界面。

### 2. 配置与窗口状态一起保存

扩展现有状态数据，分别记录不透明度上下限、四组快捷键以及原有不透明度和穿透状态。缺少新增字段时使用默认范围 0% 至 100% 和现有默认快捷键；可独立解析的旧字段不因新增字段无效而丢弃。状态文件整体无法解析时，沿用现有默认值回退行为并报告问题。

不透明度范围允许 0% 至 100%，默认范围就是整个区间，默认当前值仍是 85%。0% 在 MyGo 里要单独处理：`WindowOptions.Opacity` 对小于等于 0 的值会当成未设置并换成 1，只有 `SetOpacity(0)` 能真正生效，所以启动时在显示前再显式设置一次；真实窗口检查确认 `Opacity()` 返回 0。状态读取要区分三件事：显式保存的 0、缺少 `opacity` 字段（继续用 85%）、`settings` 里的范围字段为 null 或类型错误（该范围回退到 0%–100%）。因为 0 已经是合法值，范围字段不能用 `int` 直接解码，否则 JSON 的 null 会被读成 0。Windows 和 Linux 保持 20%–100%。

0% 时窗口仍存在，但提高快捷键仍受生效范围约束：范围上限大于 0% 时可以把窗口调回可见，上下限都是 0% 时则不能。这时只改 `state.json` 里的 `opacity` 没用，重启后仍会被保存的范围夹回 0%；要恢复必须先退出程序，同时把范围上限改到大于 0 并设置正值的不透明度，或删除整个状态文件（快捷键和穿透状态会一起重置）。实现不绕过上限，也不禁止 [0,0]；这个边界及其实际恢复路径已写入规格与 README，是否新增恢复入口留给用户决定。

不透明度范围以整数百分比表达，当前不透明度与现有窗口 API 之间在边界处转换。保存新范围时，将当前值限制到新边界，并和设置一起持久化；保存失败则恢复窗口值。继续使用临时文件写入后替换的方式，避免生成半截文件。独立配置文件也是可行方案，但会增加两个文件之间保持一致的工作，因此本次扩展现有文件。

### 3. 以动作管理快捷键并处理回滚

将四个动作、标准化组合键及其注册结果分别记录。界面只接受包含 Command、Control 或 Alt 的受支持组合，并检查标准化后的重复；平台不支持的主键或修饰键应在保存前拒绝。不同平台的默认组合继续使用现有的 `CmdOrCtrl` 语义。

保存时先校验完整草稿，再比较新旧组合。保留不变的注册，释放需要变更的旧组合后注册新组合，使两个动作交换键位也能处理。所有新注册成功且文件保存成功后，才提交生效配置；任一环节失败则撤销已完成的新注册，并尝试恢复旧注册和窗口值。系统或框架可能报告旧组合重新注册失败，因此回滚不能被假定为必然成功；应逐项记录实际结果并在界面和终端报告。

录入期间拦截应用自己的快捷键动作，避免录入隐藏或穿透组合时立即触发动作。录入结束或取消后恢复动作响应；窗口控制和注册更新均遵守框架的主线程约束。macOS 上已验证 MyGo 可以注销和重新注册快捷键，并在注销后向录入控件传递组合键。

#### 已决定：允许跨应用共享快捷键

采用 MyGo 的非独占注册，允许其他应用使用相同组合。macOS 的两进程验证中，两个进程注册相同组合均返回成功。注册成功不能证明没有其他应用使用该组合，也不能证明本应用一定会收到按键：其他应用可能同时响应，独占注册或系统行为也可能拦截通知。

设置界面应提示共享与拦截可能影响窗口恢复，建议用户选择不会被其他应用或系统拦截的组合。应用只对系统或框架实际报告的注册失败提示并处理，不将其他应用共享同一组合本身视为注册失败，也不声称能识别所有跨应用冲突。

在最小窗口中，注销后模拟组合键可送达录入控件，但模拟按键未触发系统全局快捷键回调；同一现象在独立最小程序中复现。全局快捷键的真实按键触发及窗口恢复仍需进一步验证。

### 4. 按恢复动作分别决定安全状态

启动及注册回滚后，依据各动作的已知注册结果决定窗口能否进入穿透或隐藏。穿透快捷键注册失败时，关闭已有穿透并禁止再次开启；隐藏快捷键注册失败时，确保窗口可见并禁止隐藏。其他快捷键是否成功不能替代对应恢复动作的检查。注册成功只表明系统接受了注册，并不保证之后的按键事件一定送达，因此不能据此保证所有情况下都能恢复窗口。

设置界面打开期间窗口不进入穿透；录入快捷键会先注销全部全局快捷键，此时窗口仍必须接收鼠标事件，否则失焦后既不能结束录入、也不能关闭设置。关闭设置后再按生效的穿透状态恢复。录入结束或取消后恢复旧快捷键失败时，界面和终端都要说明受影响的动作，提示保留到重新保存或恢复成功为止，不被下一次录入清空。

只有录入结束或保存回滚时真的弄丢了穿透或隐藏的恢复快捷键，才进入强制状态：清除穿透、保持窗口可见，并禁止再次开启，直到重新保存成功；只有不透明度之类的快捷键没恢复时不算。恢复失败的说明按发生顺序追加，后来的丢失不会被先前的提示盖掉，取消并重新打开设置仍能看到全部原因。启动时缺失的快捷键也不算恢复失败：隐藏键在启动时注册失败只让窗口留在可见状态，不参与穿透判断；能否进入穿透由穿透键是否可用、是否处于强制状态决定，`toggleClickThrough` 和关闭设置走同一个判断。

macOS 长按处理根据已注册组合解析主键和修饰键，而不是固定比较当前两个键位；旧的重复任务在换键、取消注册或释放按键后停止。Windows 和 Linux 继续沿用现有快捷键和窗口控制实现。

## Risks / Trade-offs

- [面板被 WebView 遮挡或无法录入系统组合键] → 先做平台验证；必要时使用独立原生设置窗口，保留规格中的交互。
- [快捷键重新注册时系统报告失败] → 显示实际失败动作，窗口回到可见且不穿透状态，并禁止已知无法恢复的动作。
- [其他应用与 GhostFish 共享快捷键或拦截事件] → 不申请独占；提示用户选择合适的组合。注册结果无法识别所有此类情况，也无法保证被拦截时恢复窗口。
- [键盘布局或系统保留键影响注册] → 在 macOS 校验并实际注册组合；不能注册时保留输入并提示。
- [旧版程序读取新版状态] → 原有字段保留原名称和含义。旧版不理解新增配置，回退后会使用旧版固定范围及快捷键。
- [用户录入按键时全局回调先于界面事件] → 在开始录入前设置动作抑制状态，并针对现有隐藏和穿透键验证事件顺序。
- [Wayland 的系统快捷键异步绑定] → MyGo 的 `Register` 返回成功及 `IsRegistered` 为真，均不能证明桌面已完成绑定；桌面还可能要求确认或修改键位。本次不修改 Linux 设置，后续支持 Wayland 时需要处理最终绑定结果。
- [上下限都为 0% 时窗口完全透明且无法用快捷键恢复] → 提高快捷键受上限约束，仍停在 0%；只改 `opacity` 也没用，重启会被范围夹回，需同时放宽上限或删除整个状态文件（后者会重置快捷键与穿透状态）。不绕过上限也不禁止 [0,0]，是否新增恢复入口待用户决定；真实窗口只验证了窗口存在且 opacity 为 0，全透明窗口能否接收鼠标未验证。

## Migration Plan

读取旧状态文件时填充缺失设置，下一次成功保存再写入新增字段。macOS 启动时先校验配置并分别注册快捷键，再根据各项结果应用穿透保护；设置损坏或注册失败均报告原因。回退到旧版时保留旧字段，新增设置由旧版忽略；回退后的可用键位和不透明度范围恢复为旧版行为。
