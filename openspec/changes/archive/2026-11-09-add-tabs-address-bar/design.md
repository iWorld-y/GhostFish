# Design

## Context

现有程序通过 `Window.Page()` 直接加载一个外部网页。启动流程在创建窗口前对目标网址执行 Basic 认证探测；窗口、不透明度和点击穿透各自保存状态。需求与行为边界见 `proposal.md` 和 `specs/`。

项目使用 MyGo v0.7.4。该版本提供原生界面、嵌入式 WebView 和保留系统窗口按钮的标题栏选项；原生界面窗口的 `Window.Page()` 为 `nil`，需要改为通过各 WebView 的 `Page()` 管理网页。

## Goals / Non-Goals

**Goals:**

- 在一个窗口内管理多个保留页面状态的 WebView，并保持第三方网页与应用控件分离。
- 复用现有窗口状态、全局快捷键和 HTTP Basic 认证规则。
- 在现有 macOS、Windows 和 Linux 支持范围内使用同一套界面结构。

**Non-Goals:**

- 不新增搜索引擎、书签、历史记录界面或跨重启恢复标签页。
- 不通过向第三方网页注入脚本来实现标签栏、地址栏或地址同步。
- 不扩展到 HTTP Basic 以外的认证方式，也不新增对网页跳转目标或子资源的认证探测。

## Decisions

### 1. 使用原生界面容纳标签栏、地址栏和网页

窗口采用 MyGo 原生界面和嵌入式 WebView。标题栏使用保留原生窗口按钮的样式，并根据平台按钮占用的区域布局标签栏；新标签页的地址栏与 WebView 放在下面，网页打开后隐藏地址栏，让 WebView 占用释放的空间。macOS 保留原生红绿灯，Windows 和 Linux 使用各自平台的窗口按钮。标签栏中选中标签以圆润的顶部轮廓与内容区衔接，并在标签内显示关闭按钮；未选中标签平铺并由必要的分隔线区分。`+` 紧随标签列表，剩余区域用于拖动；标签过多时可横向滚动。

备选方案是在网页中嵌入其他站点，但跨站限制和站点自身策略会影响加载，也会混淆应用控件与外部网页的边界。原生界面可以保持第三方页面独立，不需要向页面暴露应用方法。

### 2. 每个标签页持有一个 WebView

运行期状态记录标签页顺序、当前标签页、各自的 WebView、标题和当前网址。切换时只改变显示的 WebView，不销毁或重新加载其他页面；关闭时释放对应 WebView，关闭最后一个标签页则关闭窗口。

各标签页沿用框架的默认会话，不引入单独的 Cookie 隔离或新的持久化格式。标签页状态仅保留到进程退出，因此不带网址启动时始终打开空白页。

备选方案是用一个 WebView 反复加载不同网址，但切换时会丢失原页面状态，不满足标签页的行为要求。

### 3. 共用网址解析规则，区分输入与实际地址

启动参数和地址栏共用 HTTP、HTTPS 网址解析与协议补全规则。没有启动参数是有效的空白启动；显式提供空值、无法解析的地址或不支持的协议仍是错误。地址栏的空输入不发起导航，其他无效输入在界面提示并保留当前页面。

每个标签页独立记录是否已经打开网页。无网址启动或点击 `+` 创建的新标签页显示并聚焦地址栏；首次主文档提交后隐藏地址栏，网页占用释放的空间，不等待慢速子资源。带网址启动时默认隐藏地址栏；首次加载失败时恢复输入和错误提示，允许重试。曾打开网页的标签即使后来跳转到空白页面，也不会重新成为新标签。空输入或无效输入保留地址栏，编辑内容与错误提示可继续修改。

每个标签页仍在内部维护实际网址。导航或重定向后，通过 MyGo 的导航事件和 `Page.URL()` 更新；对平台没有发出导航事件的同文档地址变化，在窗口可见时读取当前标签页的 `Page.URL()` 补齐。这样无需注入第三方网页脚本。尚未完成首次加载的标签页再次提交时，更换该标签的 WebView，并忽略旧视图的回调；其他标签和共享会话不变。首次加载在主文档提交后失败时恢复原始提交网址；已打开的页面开始后续导航后，旧页面失败不会让标签重新显示地址栏。

### 4. 按显式提交的网址准备认证

带网址启动时，保留现有的窗口显示前探测与凭据准备；空白启动时不探测。用户在地址栏提交网址时，复用现有探测、凭据来源顺序、校验和钥匙串保存规则，再将对应主机的认证处理器安装到目标标签页的 WebView，最后加载网址。每次导航都应避免沿用其他主机的旧处理器。网址本身带凭据、无需认证或探测失败时沿用现有回退行为。

网络请求和终端输入不应阻塞窗口界面；窗口与 WebView 操作遵循框架的主线程要求。每个标签页区分当前导航与过期结果，关闭标签页或提交新网址后，不再将较早的探测结果应用到该标签页。终端凭据输入按顺序处理，避免多个标签页的提示互相交错。

备选方案是在认证质询回调中直接等待终端输入，但同步等待可能卡住界面。仍使用原有的按主机限制和被拒后停止重试规则，且不把密码写入标签页状态文件。

### 5. 窗口控制继续作用于整个窗口

置顶、整窗透明度、点击穿透、隐藏与显示继续由现有窗口级逻辑控制。开启穿透时标签栏和地址栏也不接收鼠标事件；现有全局快捷键仍是恢复窗口操作的入口。窗口隐藏后不销毁标签页。

## Risks / Trade-offs

- [原生界面和 WebView 组合后的透明度、穿透或焦点与现有窗口表现不同] → 在各支持平台验证窗口控制；重点检查 macOS 空白启动时地址栏获得焦点。
- [多个 WebView 占用更多资源] → 关闭标签页时及时释放对应 WebView，不增加后台预加载。
- [认证探测或终端输入延迟导致旧结果覆盖新导航] → 为每个标签页识别导航次序，并在标签页关闭或导航更新后丢弃旧结果。
- [窗口较窄或标签较多时控件重叠] → 为系统按钮、标签栏和拖动区域保留空间，验证窄窗口及多个标签的显示与操作。
- [脚本依赖无网址启动时的非零退出状态] → 在 README 中说明启动行为变化和调用方迁移方式。

## Migration Plan

更新启动参数说明和现有测试，不迁移或新增标签页持久化数据。回退到旧版本后，窗口状态格式保持原样，但启动命令仍须提供网址。
