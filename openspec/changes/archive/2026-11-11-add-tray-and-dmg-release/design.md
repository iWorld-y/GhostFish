# Design

## Context

当前 `main.go` 在应用就绪后创建窗口并注册快捷键。`toggleClickThrough`、`toggleHidden`、`guardRecovery` 和设置恢复逻辑把全局快捷键当作唯一恢复入口；Windows 和 Linux 的启动逻辑目前只统计已注册快捷键的总数。窗口关闭或最后一个标签页关闭会结束进程。问题和目标见 `proposal.md`。

项目使用 MyGo 0.8.3。MyGo 提供[托盘与菜单](https://mygo.egoist.dev/docs/menus)以及 [macOS DMG 打包](https://mygo.egoist.dev/docs/distribution)；Linux 托盘还依赖 AppIndicator 库及桌面托盘宿主。项目尚无 GitHub Actions 发布配置，现有单色图未跟踪，彩色 P1 尚未放入项目。

## Goals / Non-Goals

**Goals:**

- 让托盘和快捷键使用同一份窗口状态，并在可识别的恢复入口缺失时防止窗口被隐藏或穿透后无法恢复。
- 在保留现有启动参数和状态文件的前提下，增加 macOS `.app` 和通用 DMG。
- 参照 GhostPin 的标签校验、构建校验、产物上传和防覆盖流程，自动发布完整资产。

**Non-Goals:**

- 不将关闭窗口改为最小化到托盘，不新增自动更新或自动启动。
- 不改变不透明度范围或为托盘增加透明度控制；显示状态与 0% 不透明度是不同概念。
- 不新增应用内 HTTP Basic 凭据输入，也不要求本次接入 Developer ID 公证或 Gitee 同步。

## Decisions

### 使用 MyGo 托盘和共享状态

在应用就绪后创建 `mygo.NewTray`，将单色 PNG 嵌入程序，并用模板图标适配 macOS 菜单栏和 Windows 任务栏。Linux 使用 MyGo 的 AppIndicator 菜单；文档说明系统库及桌面托盘宿主要求。托盘对象的生命周期与应用一致。

托盘菜单提供穿透勾选项、动态的显示或隐藏项以及退出项。托盘回调与快捷键调用同一组窗口控制函数，菜单项从应用状态更新，避免维护第二份穿透或可见状态。窗口关闭和最后一个标签页关闭继续退出；隐藏窗口只调用隐藏动作，不销毁网页视图。

设置打开期间保留用户选择的穿透配置，但实际暂停鼠标穿透，并在托盘菜单中说明暂停状态。录入或保存快捷键失败时，仍立即保持窗口显示且不穿透，保留错误提示；用户关闭设置后可在托盘已知可用时主动重新开启穿透或隐藏窗口。

备选方案是在各平台直接维护原生托盘实现，但现有框架已提供所需菜单和生命周期接口，重复实现会增加平台代码。

### 按动作判断恢复入口

将托盘可用性与每个快捷键的注册结果分别记录，避免 Windows 和 Linux 只用快捷键注册总数推断恢复能力。启动时先创建窗口和托盘，再完成快捷键注册及恢复判断，最后应用保存的穿透状态并显示窗口。

| 托盘菜单 | 对应快捷键 | 处理方式 |
| --- | --- | --- |
| 已知可用 | 任意 | 允许相应动作，并可从托盘恢复 |
| 不可用或无法确认 | 已注册 | 允许相应动作，保留快捷键恢复方式 |
| 不可用或无法确认 | 未注册 | 禁止相应的穿透或隐藏动作；启动时清除无法恢复的穿透状态 |

托盘创建失败时保留终端错误，并通过不依赖主窗口不透明度的原生提示说明原因和恢复方式。该提示不修改用户设置的不透明度，即使窗口为 0% 也应可见。

Linux 的 `NewTray` 成功不等于桌面一定展示图标。应通过 [StatusNotifier 宿主状态](https://specifications.freedesktop.org/status-notifier-item/latest/status-notifier-watcher.html)等平台信号确认入口，监听可检测的宿主消失和恢复；无法确认时按托盘不可用处理。标准定义了宿主注册信号，但没有规定宿主注销信号，因此还需结合总线状态变化或重新读取宿主属性，不能只监听注册信号。若托盘恢复或用户实际调用托盘菜单，再更新可用状态。宿主消失时分别检查两个动作：穿透快捷键不可用则关闭并保存穿透状态，显示快捷键不可用则显示窗口；不影响仍有恢复入口的动作。系统可能隐藏图标或拦截已注册快捷键，不能把注册成功视为事件一定送达。

### 图标、状态与图形启动

实施时将用户选定的彩色 P1 和原工作区未跟踪的 `assets/logo/ghostfish-monochrome.png` 复制到变更分支，并纳入版本管理。CI 只读取仓库中的资源，不依赖本机生成目录。托盘图标应在常见小尺寸、浅色和深色背景下检查；如果原图细节无法辨认，保留角色和鱼的主要轮廓并制作适合小尺寸的同款资源。

macOS 应用沿用 `GhostFish` 应用名和用户数据目录，保持现有位置、尺寸、不透明度、穿透状态与设置的读取方式。使用稳定的应用标识，并保留当前不显示 Dock 图标的行为。图形入口不传网址时打开空白标签页；命令行参数、版本查询和关闭语义保持兼容。

图形入口没有终端。HTTP Basic 认证仍先查环境变量和系统钥匙串；没有凭据且无终端时沿用 WebView 回退，不等待终端输入。不同系统是否显示 WebView 认证界面需要验证，不承诺自动弹出登录框。

### macOS 打包与版本

采用与运行时版本一致的 MyGo CLI 构建 `darwin/universal`，在 macOS runner 生成包含 `GhostFish.app` 和 Applications 入口的 DMG。应用配置提供彩色图标、稳定的 bundle identifier、`LSUIElement` 和项目已有的最低 macOS 版本。默认采用临时签名，不配置公证凭据。

以受版本管理的应用配置版本作为唯一版本来源，发布标签使用对应的 `vX.Y.Z`。打包时将同一版本用于 DMG 文件名、应用元数据和四个命令行程序。现有 `main.version` 通过 `go build -ldflags` 注入；MyGo 打包使用自身的构建参数，不能假定 `GOFLAGS` 能覆盖它。应用的版本查询应兼容打包元数据与现有注入方式，并统一输出与标签一致的版本。

备选方案是单独维护两份架构的 DMG 或复制 GhostPin 的 Swift 打包脚本。通用 DMG 减少下载选择，MyGo 的 Go 打包流程更贴合当前项目。

### GitHub Actions 发布

工作流借鉴 GhostPin 的 `v*` 标签和手动触发方式。元数据阶段校验受版本管理的版本与标签；各平台构建并运行相应测试；macOS runner 生成并挂载 DMG，检查应用、图标、两种架构、签名和映像完整性，再上传工作流产物。

发布阶段只在匹配的标签推送且全部构建和校验成功后运行，下载并检查五个预期文件，再使用最小必要的仓库写权限创建 Release。先确认目标 Release 确实不存在；权限不足或网络错误不能当作不存在。上传期间使用草稿，确认完整后再发布；并发创建冲突或任何检查失败时停止，不得覆盖已有 Release，也不得公开不完整资产。手动触发只生成可下载的工作流产物，不创建 Release。

四个现有命令行文件继续沿用 README 中的名称，避免中断现有下载链接。若上传失败留下本次草稿，重新运行前需显式处理该草稿，不能用覆盖参数修改已有发布物。

## Risks / Trade-offs

- [托盘宿主可能不存在或之后消失] → 区分图标创建与宿主可用，分别判断每个快捷键，并验证宿主变化和失败提示。
- [0% 不透明度下显示窗口仍不可见] → 托盘不擅自改变透明度；文档保留现有恢复方法并说明该限制。
- [图形启动没有终端] → 验证 Basic 认证回退及错误提示，不把 WebView 的登录交互当成已验证能力。
- [未公证 DMG 被 Gatekeeper 拦截] → 延续未公证发布，更新安装说明并参考 [Apple 的 Gatekeeper 说明](https://developer.apple.com/news/?id=saqachfa)；后续需要平滑安装时再配置 Developer ID 和公证。
- [图标源文件不在新 worktree] → 实施时从当前会话和原工作区复制选定图片，检查后提交资源；CI 不能引用本地缓存。
- [MyGo 打包与命令行版本注入不同] → 将两个发布路径的版本输出列入构建校验，不依赖未经验证的链接参数。

## Migration Plan

先实现并验证托盘与资源，再加入 macOS 打包和工作流。保留既有状态目录与四个命令行产物，更新 README 的下载、首次打开和托盘故障说明。

现有 `openspec/specs/control-surface/spec.md` 的 Purpose 仍描述「没有菜单栏图标」；该文字应在功能实施完成后按规格同步流程更新，不在提案阶段提前改写当前事实。回退时可停止新工作流并恢复此前的命令行发布；旧状态文件不需要迁移。
