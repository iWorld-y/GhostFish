# Design

## Context

当前 `authPrompt` 按标签页保存输入和认证状态。`showAuth` 仅为当前标签页显示认证窗口，`syncAuthTab` 在切换时隐藏和恢复独立窗口。主窗口的显示、穿透与不透明度由桌面控制器管理，独立认证窗口不受这些状态约束。

## Goals / Non-Goals

**Goals:**

- 让认证表单作为当前标签页内容参与主窗口绘制，并保留各标签的认证状态。
- 让认证期间仍可操作标签栏，后台认证请求不抢占当前标签页和焦点。

**Non-Goals:**

- 不修改凭据获取、校验、保存顺序或 HTTP Basic 认证范围。
- 不改变主窗口的托盘、快捷键和穿透恢复策略。

## Decisions

### 使用标签页内容区域承载表单

在浏览器视图中保留标签栏，根据当前标签页是否有待显示的认证请求，在内容区域选择绘制认证表单或网页视图。表单使用已有的 `authPrompt`，避免把认证输入注入外部网页。认证结束后恢复该标签页的正常内容，仍由现有认证流程决定导航和取消。

备选方案是保留独立窗口并同步主窗口状态，但仍需处理窗口位置、层级和焦点，且不符合表单位于标签页内容区域的要求。

### 认证状态归标签页管理

继续使用每个标签页的 `authPrompt` 和导航代次校验。认证状态变化时刷新主窗口，切换标签页只改变可见内容，不取消后台认证。关闭标签页、导航、取消或退出时沿用现有清理逻辑，清除密码并防止过期异步结果生效。焦点只在当前可见表单需要输入时处理，后台请求不主动聚焦或显示主窗口。

备选方案是把表单状态集中到主窗口，但多个标签并行认证需要额外映射，容易混淆请求和输入。

### 沿用主窗口状态

表单成为主窗口内容后，隐藏、鼠标穿透和不透明度由现有窗口控制统一生效，无需引入第二套同步状态。切换到认证表单时应验证框架对原生 WebView 的显示和层级处理，避免网页覆盖表单或仍接收鼠标。

## Risks / Trade-offs

- [原生 WebView 与表单的层级或焦点行为因平台而异] → 使用真实窗口验证替换内容、切换标签和恢复网页；保留 WebView 实例及页面状态。
- [小窗口可能无法容纳完整表单] → 在现有最小尺寸和窄窗口下验证输入、错误提示及操作按钮可访问。
- [异步认证回调与标签切换、关闭或导航交错] → 保留代次和有效性检查，并用定向测试覆盖过期结果与多标签隔离。
